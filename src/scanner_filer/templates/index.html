❓ Help & Reference

System Overview

This is the Home Document Ops Hub — a self-hosted PDF document pipeline running on a Raspberry Pi. It watches a scanner inbox folder, automatically OCRs, classifies, splits, and files every PDF that arrives.

Documents flow through three stages:

  1. Inbox / Queue — raw scan lands here from your scanner or network share. Waits for the file to settle (configurable), then enters processing.
  2. Processing — OCR is applied, pages are analysed for split points, the document is classified by type (invoice, pension, vehicle, etc.) and a sender is extracted. The result is filed automatically.
  3. Archive / Review / Rejected — the final resting place. Archive = confidently filed. Review = needs a human decision (low confidence or unknown type). Rejected = failed to process.
Processing Queue Panel

The queue panel shows every file currently waiting or being processed in real time (updates every 5 seconds automatically).

  • waiting_for_settle — file has arrived in the inbox but is still within the settle period. This prevents processing half-written files from slow scanners.
  • processing — file is actively being OCR'd and classified right now.
  • stuck (Nm) — file has been in the processing folder for more than 5 minutes without progress. This usually means the scanner-filer service crashed mid-job.
  • orphaned_processing — file is in the processing folder but no active job is currently running against it (recently stopped).

♻ Rescue Stuck Files — moves all stuck/orphaned files back to the inbox so they are automatically reprocessed. The actively-processing file (if any) is always skipped. Use this if a file appears stuck for more than 10 minutes.

When the queue empties after having items, the page reloads automatically to refresh the document list and tree.

Directory Tree

A live browsable folder view of all files across Archive, Review, and Rejected. Mirrors exactly what is on disk.

  • Expand All / Collapse All — open or close all folder nodes at once.
  • Filter box — instantly hides any tree branches that don't match the typed text. Clears when empty.
  • 📄 Open — opens the PDF directly in a new browser tab.
  • 🔍 (magnifier) — locates the file in the Document List below, scrolls to it, expands its detail row, and briefly highlights it in yellow.

Archive folder structure is: type / year / sender / filename.pdf (or username / type / year / sender / filename.pdf for per-user inboxes).

Document List

A searchable, sortable table of every document in Archive, Review, and Rejected.

Search & Filter

  • The search box matches against filename, folder path, sender, category, and keywords.
  • The bucket filter dropdown limits results to Archive, Review, or Rejected only.
  • Sort options: Time Received, Last Processed, Folder Location, Category, Sender, Size, Filename, Status (Review first, then Rejected, then Archive).

Status Chips

  • archive — filed and complete.
  • review — needs your attention. Classification was uncertain or unknown.
  • rejected — processing failed.
  • 0.0-1.0 — AI confidence chip shown next to the status chip. 1.0 is strongest confidence (green), 0.0 is weakest (red), with a red-to-green gradient in between.
  • username — document belongs to a specific user inbox.
  • auto-filed — was archived automatically by the pipeline within your configured highlight window (10m, 1h, 1d, 1w, or forever).

Expanding a Row

Click any row to expand its detail panel. Click again to collapse.

Bulk Actions

Use the checkboxes on the left to select multiple files. Then:

  • Transfer Selected — moves all selected files to the chosen inbox user's archive (or the default archive). Requires selecting a destination inbox from the dropdown.
  • Reclassify Selected — sends all selected files back to the inbox for fresh classification from scratch. No inbox selection needed.
  • Select all visible checkbox — selects every visible row at once.
Document Detail Actions (expanded row)

Keywords

Each document has a set of automatically extracted keywords derived from its OCR text. These are used for search and can influence re-classification. You can edit them manually and click Save Keywords — your manual keywords take priority over automatically extracted ones and persist across reprocessing.

Move (Learn)

Moves the file to the Archive with the category, year, and sender you specify. This is the primary way to correct a wrong classification. When you move a file:

  • A manual learning record is saved — next time a document with similar keywords arrives, it will be matched against this record and classified the same way.
  • Any strong, specific keywords from the document are injected into the keyword override rules, so the classifier will recognise the same pattern in future without needing an LLM call.

Learning can be disabled globally in Setup → AI Filing Behaviour.

Tip: leave the sender field blank if unknown — it will be filled as "unknown" in the folder path.

Add Category

Adds a new document type/category to the allowed list so the AI can classify future documents into it. The category name must be lowercase letters, numbers, underscores, or spaces (2–40 chars). Takes effect immediately for the UI; restart the scanner-filer service to use it in classification.

Split + Reprocess

Splits the PDF at the page numbers you specify (1-based, comma-separated, e.g. 1,4,7) and sends each part back to the inbox for independent reprocessing. Use this when the scanner has merged multiple documents into one PDF. Each part is processed separately and filed according to its own content.

Reclassify

Sends the file back to the inbox to be reprocessed from scratch — OCR, classification, and filing all run again. Any manual learning records and keyword overrides learned from previous moves will be applied. Use this after fixing keyword overrides or category rules to apply them to an existing document.

Delete

Permanently deletes the file from disk. This cannot be undone. A confirmation dialog is shown before deletion.

AI Classification & Learning

The classification pipeline runs in this order:

  1. LLM classification (primary) — the local model reads OCR text and makes the first classification decision.
  2. AI ruleset guidance in prompt — the model receives your configured role descriptor, guidance, and AI ruleset context while deciding.
  3. Manual learning correction — if prior manual moves strongly match this document, the learned type can override to keep future filing consistent.
  4. Safety guards — negative keywords can downgrade risky classifications to Review.
  5. Public knowledge assist (optional) — if enabled, acronym hints are used mainly for weak/unknown outcomes.
  6. Keyword fallback (last resort) — keyword heuristics are used only when the LLM is disabled, times out, fails, or returns unusable output.
  7. Filing threshold — if final confidence is below threshold, the document is sent to Review instead of Archive.

LLM Role Descriptor

This field defines the classifier's mission in plain language (for example: classify by semantic intent first, avoid keyword-only guesses). Use it for stable, top-level behavior; use Classification Guidance for edge cases and exceptions.

Category Suggestions (New)

If the LLM is confident a document does not fit any existing category, it can suggest a new category name (snake_case). In Setup you can choose one of two modes:

  • Suggest only — the system records the suggestion metadata, but does not change your allowed category list automatically.
  • Auto-create on high confidence — if enabled, suggested categories are added automatically only when suggestion confidence is above your configured threshold.

Recommended: start with Suggest only, review behavior for a few days, then enable auto-create if suggestions are consistently accurate.

Confidence Threshold

Set in Setup → AI Filing Behaviour. Documents with a confidence score below this value go to Review instead of Archive.

LLM Output Reliability

The classifier enforces strict JSON shape and confidence bounds before a result is accepted. Invalid or malformed model output is rejected and handled by the fallback path rather than being trusted blindly.

In Setup → Runtime & Engine, the JSON reliability card shows current health (failure rate, consecutive failures, fallback triggers, and active mode).

Public Acronym Options (Important Difference)

  • Enable public acronym knowledge assist — turns on acronym detection and local acronym mapping only. No internet required. Safe default if you want privacy-first behaviour.
  • Allow online acronym lookup (token-only) — optional extra fallback used only when local mapping does not resolve an acronym. Sends just the acronym token (for example ABCP) to the Wikipedia summary API, never OCR text or document content.

Recommended: keep knowledge assist ON, keep online lookup OFF by default, and add your frequent acronyms to the local override map for fastest and most predictable results.

Keyword Extraction Settings

  • Max OCR chars — how much of the OCR text is analysed for keyword extraction (default 5000).
  • Keyword/phrase count — maximum number of keywords stored per document (default 24).
  • Include phrases — if enabled, 2- and 3-word phrases are extracted alongside single words (weighted higher).
  • Infer year from text — scans OCR text for the most common year reference and uses it as the default move year.

Keyword Override Rules

A JSON map of "phrase": "type" entries. These are now treated as controlled override hints and are mostly applied in fallback/low-signal paths rather than replacing strong LLM decisions. Keep phrases specific (multi-word) to avoid false positives. Example: {"mot test certificate": "vehicles", "annual benefit statement": "pension"}.

Negative Keywords

A JSON map of "type": ["word1", "word2"]. If a document would be classified as that type but any of those words appear in the text, the classification is rejected and the document goes to Review. Useful for preventing false positives.

Setup: NAS & Storage
  • NAS Host/Share — connect the Pi to your network-attached storage where archived documents are written.
  • Mount Point — where the NAS share is mounted on the Pi filesystem (e.g. /mnt/nas).
  • Subdir — subfolder inside the NAS share used as the root for all filing (e.g. Home Filing).
  • Scanner Share — the Samba share on the Pi that your scanner deposits files into. The inbox folder watches this location.
  • Inbox Settle Time — seconds to wait after a file appears before processing it. Prevents reading incomplete uploads from slow scanners.
Setup: User Inboxes

User inboxes allow multiple household members to have their own separate archive, review, and rejected folders on the NAS. Each user can have documents filed into their own directory structure independently.

  • Add User — creates a new user with their own NAS paths for archive, review, and rejected folders.
  • Edit / Remove — update or delete a user's configuration.
  • Samba Share — a dedicated Samba share can be created on the Pi for each user's scanner inbox, so a user's scanner uploads go directly into their queue.

When transferring documents in bulk, select the destination user from the inbox dropdown in the bulk action bar.

Setup: Runtime & Engine

These controls tune processing cadence, stability checks, and model engine behavior.

  • poll_seconds — how often the watcher scans the inbox for new files.
  • inbox_settle_seconds — minimum file age before processing starts.
  • require_size_stability / stable_cycles_required — prevents processing files that are still growing on disk.
  • LLM timeout / max input chars — controls model latency and prompt size.
  • LLM profile — Fast, Balanced, Deep, Ultra, or Custom. Non-custom profiles auto-build a command for an available local model and keep structured JSON output constraints enabled.
  • LLM JSON reliability panel — live view of JSON failure rate, consecutive failures, fallback activity, and last result mode to quickly detect model-output drift.
  • LLM/OCR enabled — hard on/off switches for classification and OCR engines.
  • log level — DEBUG/INFO/WARNING/ERROR runtime verbosity.
Setup: Splitter

The splitter decides whether a multi-page PDF contains a single document or several documents that should be filed separately.

  • Min pages per split — a document part must have at least this many pages to be filed as a standalone document.
  • Max pages per split — the maximum number of pages that can be grouped into a single document part.
  • Boundary keywords — keywords that suggest the first page of a new document.
  • Boundary score threshold — how different two adjacent pages need to be (0.0–1.0) to be treated as a document boundary when content-aware splitting is enabled.
  • Low similarity threshold — lower threshold used to force splits when adjacent pages share very little text overlap.
  • Content-aware splitting — uses text similarity between pages to detect where one document ends and another begins, rather than always splitting at fixed page counts.

Manual Split (in document detail) lets you override automatic splitting for a specific file by specifying the exact page numbers where splits should occur.

Setup: Security & Accounts

Controls login access to this web interface.

  • Add Account — creates a new username/password for the web UI. Passwords are stored hashed.
  • Remove Account — revokes access for a user. You cannot remove the last remaining admin account.

The web UI uses session cookies. Sessions expire after closing the browser or after a configurable timeout.

Backup & Restore

The Download Backup option creates a .tar.gz archive containing:

  • Your config.yaml (all settings)
  • The state/ folder (manual learning records, keyword index, event log, rules)
  • The runtime/processing/ folder (any files currently being processed)

The Restore option uploads a previously downloaded backup and replaces the current config and state. The service restarts automatically after restore. Document files themselves (archive/review/rejected) are not included in the backup — these live on the NAS.

Tips & Troubleshooting
  • High unknown/review rate — check your keyword override rules. Short common words like "car", "total", "act" cause false positives. Keep overrides to specific, precise phrases.
  • File stuck in processing — use ♻ Rescue Stuck Files in the Queue panel to move it back to inbox.
  • Wrong classification corrected by Move (Learn) — the system records your correction. Future documents with similar content will be classified the same way automatically.
  • Acronyms not recognised — add them to the Acronym Override Map in Setup → AI Filing Behaviour (e.g. {"acronym_name": "pension"}).
  • Document split incorrectly — use Split + Reprocess in the document detail to manually specify the correct page boundaries.
  • Services — two systemd services run the system: scanner-filer (background watcher/processor) and scanner-filer-web (this web interface). Both must be active for full functionality.
